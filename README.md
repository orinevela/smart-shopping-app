# עגלה חכמה — אפליקציית קניות סופר חכמה

MVP (שלב 1 מתוך מסמך האפיון): רשימות קניות חכמות + השוואת מחירים ומבצעים
בין חנויות, מבוסס על נתוני מחירון (בדוגמה זו — נתוני seed, ראו הערה למטה).

Stack: Next.js (App Router) + TypeScript + Prisma/PostgreSQL + Tailwind CSS v4.
Hebrew, RTL, mobile-first.

## פריסה ל-Vercel

1. **מסד נתונים** — ב-Vercel: Storage tab → Create Database → Postgres
   (מבוסס Neon). זה מוסיף אוטומטית משתני סביבה של DATABASE_URL לפרויקט.
   (אפשר גם Neon/Supabase חיצוני ולהדביק את מחרוזת החיבור ידנית.)
2. ב-Vercel → New Project → ייבוא הריפו `orinevela/smart-shopping-app`.
3. הוספת משתני סביבה בפרויקט (Settings → Environment Variables):
   - `JWT_SECRET` — מחרוזת אקראית ארוכה.
   - `SEED_SECRET` — מחרוזת אקראית (רק כדי להריץ את זריעת נתוני הדמו פעם
     אחת אחרי הפריסה הראשונה — ראו מטה).
   - `DATABASE_URL` כבר קיים אם נוצר מ-Storage tab; אחרת להוסיף ידנית.
4. Deploy. שלב ה-build מריץ `prisma generate && prisma db push && next
   build`, כך שהסכימה נוצרת אוטומטית במסד הנתונים בכל פריסה (מתאים ל-MVP;
   פרויקט production אמיתי יעבור ל-`prisma migrate deploy` עם מיגרציות
   שמורות ב-git).
5. **זריעת נתוני דמו** (פעם אחת, אחרי הפריסה הראשונה — אין גישת shell
   לסביבת Vercel כדי להריץ `npm run db:seed`, אז יש endpoint ייעודי):
   ```bash
   curl -X POST https://<your-app>.vercel.app/api/admin/seed \
     -H "Authorization: Bearer <SEED_SECRET>"
   ```
   זה יוצר משתמש דמו (`demo@shop.app` / `shop1234`), 4 חנויות ו-22 מוצרים
   עם מחירים ומבצעים. אפשר להריץ שוב בכל עת כדי לאפס לנתוני הדמו המקוריים.

## הרצה מקומית

```bash
npm install
cp .env.example .env       # set DATABASE_URL to a real Postgres + a real JWT_SECRET
npm run build                # runs prisma generate + db push, then builds
npm run db:seed             # demo user, 4 stores, ~22 products with prices/promos
npm run dev
```

פתחו http://localhost:3000 והתחברו עם משתמש הדמו (סיסמה: `shop1234`):

| אימייל | תיאור |
| --- | --- |
| demo@shop.app | כולל מיקום בית (תל אביב), רשימה פעילה, ושתי רשימות בהיסטוריה |

## מבנה המערכת ותכולת ה-MVP

מיישם את חלק א' (רשימות) במלואו וחלק ב' (השוואת חנויות) על בסיס מחירון,
בהתאם לשלב 1 בסעיף 8 של מסמך האפיון:

- **רשימות** (`/lists`) — יצירה, עריכה, שיוך פריט למוצר בקטלוג עם השלמה
  אוטומטית (`/api/products/search`) או כטקסט חופשי, כמות ויחידת מידה,
  סימון "נקנה", מיון לפי קטגוריה בסדר שממזער חשיפת קירור/קפואים.
- **היסטוריה** (`/history`) — רשימות שהושלמו, עם שכפול כרשימה חדשה.
- **הצעות פריטים חוזרים** — מוצגות בעמוד הרשימה, מבוססות על פריטים שנקנו
  לפחות פעמיים ב-3 החודשים האחרונים (`src/lib/recurring.ts`).
- **שיתוף בסיסי** (`/s/[token]`) — קישור שיתוף לצפייה או לעריכה (סימון
  פריטים) ללא צורך בהתחברות; לא כולל עדכון בזמן אמת בין משתתפים.
- **הגדרות** (`/settings`) — מיקום בית (כתובת/קואורדינטות, כולל שימוש
  ב-GPS של הדפדפן) ורדיוס חיפוש חנויות.
- **השוואת מחירים** (`/lists/[id]/compare`) — לכל אחת מעד 3 החנויות
  הקרובות ברדיוס שהוגדר: עלות כוללת של הסל, פירוט פריט-פריט, מקור וזמן
  עדכון אחרון של המחיר (רמת אמינות), השוואת קנייה עצמית מול משלוח (דמי
  משלוח, מינימום הזמנה, זמן אספקה משוער מול זמן נסיעה משוער).
- **התאמת כמות למבצע** (סעיף 5.3) — כשיש מבצע על כמות שונה מזו שברשימה,
  מוצגת הצעה מפורשת לחיסכון הצפוי; שינוי הכמות קורה רק באישור המשתמש
  (לחיצה על "התאמת כמות"), לא אוטומטית.

### מחוץ לתחום ה-MVP הזה (לפי שלבי הפיתוח במסמך)

פיצול סל אוטומטי בין חנויות, נעילת חנות לפריט, מתכונים → רשימה
אוטומטית, תזכורות מלאי בבית, סינון תזונתי/אלרגיות, תקציב לרשימה, מסלול
הליכה בתוך החנות, סריקת ברקוד/קול, וזמינות מלאי בזמן אמת — כולם שלב 2/3
במסמך האפיון ולא מומשו כאן.

## הערה על מקור נתוני המחירים

כפי שמצוין בסעיף 3 של מסמך האפיון, אין API ציבורי אחיד למחירי סופרים.
לצורך הדגמה, `prisma/seed.ts` יוצר 4 חנויות ומחירים לדוגמה (כולל מבצעים
ומחיר אחד מסומן כ"דיווח משתמשים" להדגמת אינדיקציית האמינות). כדי לחבר
מקור אמיתי — למשל קבצי מחירון פומביים (XML/JSON יומיים) — יש להחליף רק
את שכבת ה-ingestion שממלאת את טבלת `Price` (ראו `prisma/schema.prisma`);
שאר הקוד (חישוב סל, השוואת חנויות, תצוגה) עובד מול הסכימה בלי תלות
במקור הנתונים.

## מודל נתונים

`prisma/schema.prisma` — `User` / `HomeLocation` / `Store` / `Product` /
`Price` (כולל שדות מבצע: `promoLabel` / `promoUnitPrice` / `promoMinQty`
ו-`source`) / `ShoppingList` / `ShoppingListItem` / `ListShare`. ערכים כמו
קטגוריה/יחידה/סטטוס הם מחרוזות (לא enum מקורי) עם הערה בסכימה; הערכים
המותרים מוגדרים ב-`src/lib/constants.ts`.

## מגבלות ידועות (לא במסגרת ה-MVP)

- **עבודה אופליין** (סעיף 7 במסמך) אינה ממומשת — נדרש חיבור לאינטרנט.
- מרחקים בין מיקום הבית לחנויות מחושבים כקו אווירי (Haversine), לא לפי
  מסלול נסיעה בפועל.
